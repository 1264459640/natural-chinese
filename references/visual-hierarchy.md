# 信息架构与视觉排版规范 (Visual Hierarchy & Formatting)

本文档是 `natural-chinese` 的子集引用规范，专门解决**“文字虽然已经不带机翻腔，但整篇排版依然让人读得眼花、头累、心累”**的视觉与认知摩擦问题。

---

## 1. 为什么“写得对”依然“读得累”？（排版病理剖析）

在消除了语法级翻译腔和工匠黑话之后，很多输出依然让读者产生强烈的抗拒感。病根在于**忽视了人类视觉扫视（Scanning）的生理习惯**：

| 视觉病症 | 典型表现 | 读者的真实生理反馈 |
| :--- | :--- | :--- |
| **分号堆砌文字墙** | 4~6 件不同性质的事情，用分号串在长达 4 行的段落里。 | 视线找不到着陆点，阅读被迫降级为逐字精读，产生烦躁感。 |
| **裸露的决策请示** | 抛出“是 A 还是 B？你看这样行不行？”的裸露问句。 | 产生“决策疲劳”，读者必须在大脑中自行推演 A 和 B 的利弊。 |
| **缺乏视觉锚点** | 全文只有黑白灰纯文本，没有状态符号、粗体首词或视觉等级。 | 3 秒内无法判断“事情搞定了没有”、“我要不要立刻拍板”。 |
| **公文大纲式死板** | 死板套用“一、二、三、四”，层级生硬，缺乏呼吸感。 | 形式感过重，公文八股的味道挥之不去。 |

## 2. 现代高效沟通四大排版原则

### 原则一：3 秒仪表盘法则（Dashboard at a Glance）
- 顶部必须有直观的状态概览，用状态标牌（`✅ 已完成`、`⏳ 待定夺`、`⚠️ 需注意`）替代大段过程描述。
- 读者只看前 3 行，就应当能掌握全局生死状态。

### 原则二：决策必带推荐（Decisions with Recommendations）
- 永远不要只抛出问题。必须给出：
  1. **背景现状**（1 句话说清矛盾点）。
  2. **你的推荐选项**（明确标注“推荐方案”）。
  3. **推荐理由**（1 句话说清收益或风险对冲）。
- 变“让领导做论述题”为“让领导做选择题甚至确认题”。

### 原则三：信息原子化（Atomic Information）
- **一条信息只占一行**。
- 坚决杜绝“段落内分号连缀”。凡是并列事项（如 5 个遗留 Bug、4 处配置变更），强制使用点阵列表（Bullet Points）。

### 原则四：渐进式呈现（Progressive Disclosure）
- 次要技术细节、次级配置文件清单、历史技术债，使用 Markdown `<details>` 标签优雅折叠，或作为附录。
- 把正文黄金区域留给：**核心结论** 与 **待办决策**。

## 4. 终审排版自检清单 (Formatting Checklist)

在发送或展示结构性内容前，扫视自测：
- [ ] **拒绝文字大山**：是否存在超过 3 行且没有点阵分隔的长文本段落？
- [ ] **拒绝分号堆砌**：是否有多个并列事项被分号挤在同一段内？（如果有，强制拆成 Bullet Points）
- [ ] **决策必须给倾向**：凡提出需要拍板的问题，是否给出了“推荐方案 + 一句话理由”？
- [ ] **3 秒抓取状态**：顶部是否有明确的 Badge（`✅`、`⏳`、`⚠️`）展示结果状态？
- [ ] **细节按需收纳**：次要的配置清单与低危遗留问题，是否使用了折叠标签（`<details>`）或附录处理？
